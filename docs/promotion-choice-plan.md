# เลือกโปรหน้างาน (E51)

ตัดสินใจ 2026-11-08: เมื่อโปรที่เข้าเงื่อนไขใช้ร่วมกันไม่ได้ แคชเชียร์เลือกเองได้ แทนที่ระบบจะยึดเลขลำดับอย่างเดียว

## การตัดสินใจ

1. เลือกครั้งเดียว มีผลกับทุกบรรทัดที่มีตัวเลือกชุดเดียวกัน (สินค้า serial แยกบรรทัดละชิ้น และของแถมนับรวมหลายบรรทัด)
2. `priority` เป็นค่าเริ่มต้น แคชเชียร์ไม่ต้องเลือกถ้าลูกค้าไม่ขอ
3. แคชเชียร์เลือกได้เลย ไม่ต้องขออนุมัติ — ทุกตัวเลือกเป็นโปรที่ admin ตั้งไว้ และบิลบันทึกโปรที่ใช้จริง (`SaleLine.promotionIds`, `Sale` ระดับบิล)

## กติกา (`pos-pricing.model.ts`)

- `promotionChoices: number[]` ของบิล เรียงใหม่สุดก่อน ไม่มี = คิดตาม `priority` เหมือนเดิม
- ใช้แยกกันในสองระดับ (โปรสินค้า / โปรท้ายบิล): ดูตัวที่เลือกล่าสุดซึ่งเป็นผู้สมัครและเข้าเงื่อนไข
  - ไม่ใช้ร่วม → ใช้ตัวนั้นตัวเดียว
  - ใช้ร่วมได้ → ใช้ตัวที่ใช้ร่วมได้ทั้งหมดตามลำดับ และตัดตัวที่ไม่ใช้ร่วมออก
  - ไม่เข้าเงื่อนไข / หมดอายุ / ไม่รู้จัก → ไม่สนใจ (ไม่ใช่ error)
- ตัวเลือกที่แคชเชียร์เห็น (`promotionConflicts()`, หน้าบ้านเท่านั้น): โปรไม่ใช้ร่วมแต่ละตัว = 1 ตัวเลือก, โปรใช้ร่วมได้ทั้งหมด = 1 ตัวเลือก; มีตั้งแต่ 2 ตัวเลือกจึงแสดงปุ่ม "เปลี่ยนโปร"
- การเลือกใหม่ไม่ลบตัวเก่าออกจากรายการ บรรทัดกลุ่มอื่นจึงยังยึดตัวที่เลือกไว้

## ลำดับ deploy

an22-api ต้องขึ้นก่อนหน้าบ้าน: ไม่ส่ง `promotionChoices` = ผลเหมือนเดิม แต่ถ้าหน้าบ้านขึ้นก่อน การเปลี่ยนโปรจะได้ 400 "ราคาหรือโปรโมชั่นมีการเปลี่ยนแปลง…"
