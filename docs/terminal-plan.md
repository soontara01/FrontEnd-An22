# แผนทะเบียนเครื่อง POS (หลายเครื่องต่อร้าน)

สถานะ: **เสร็จ (2026-10-12)** · ขั้นที่ 1–7 ครบ · ข้อตัดสินใจ T1–T5 ยืนยันครบแล้ว (2026-10-12; T4 = รันเลขต่อเนื่องแยกตามเครื่อง)

ที่มา: ระบบกะรองรับหลายเครื่องต่อร้านแล้ว (`docs/shift-plan.md` หัวข้อ 1: 1 เครื่องเปิดได้ทีละ 1 กะ) แต่เอกสารภาษียังคิดแบบ
1 ร้าน = 1 POS — ร้านไอที / เครื่องใช้ไฟฟ้ามักมีมากกว่า 1 เครื่อง จึงไม่รอถึง SaaS (`saas-plan.md` หัวข้อ 5 เดิมเลื่อนไว้)

## 1. ปัญหาตอนนี้

|         | `terminalId` (เลขเครื่อง)                                   | `posId` (POS ID สรรพากร)                                   |
| ------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| คือ     | เลขลิ้นชัก / เครื่องในร้าน 1, 2, 3                          | หมายเลขเครื่องที่กรมสรรพากรอนุมัติ เช่น `E051234567890`    |
| เก็บที่ | localStorage ของเครื่อง (`TerminalService`, `pos.terminal`) | `StoreInfo.posId` — **ค่าเดียวทั้งร้าน**                   |
| ใช้     | ผูกกะกับลิ้นชัก (`X-Terminal-Id`)                           | พิมพ์ "POS ID …" บนใบกำกับอย่างย่อ / ใบกำกับ 80 มม. / ใบ Z |

1. ร้านมี 3 เครื่อง → ใบเสร็จทุกเครื่องพิมพ์ POS ID เดียวกัน ทั้งที่สรรพากรออกเลขให้**แต่ละเครื่อง**
2. แคชเชียร์พิมพ์เลขเครื่องเองได้ทุกครั้งที่เปิดกะ (`OpenShiftDialog`) → เลขซ้ำ / เลี่ยงเครื่องได้, ล้าง browser แล้วเลขหาย
3. หน้าจอเรียกทั้งสองค่าว่า "เครื่อง POS" / "หมายเลขเครื่อง POS" → สับสน
4. `Sale` ไม่เก็บว่าออกจากเครื่องไหน (มีแค่ `shiftId`; ปิด `requireShift` แล้วไม่รู้เลย) → พิมพ์สำเนาย้อนหลังไม่รู้ว่าต้องใช้ POS ID ไหน

## 2. หลักการ

- **เลขเครื่องผูกกับเครื่อง (ลิ้นชัก) ไม่ใช่ผู้ใช้** — แคชเชียร์ย้ายเครื่องได้, หลายคนใช้เครื่องเดียวกันต่างกะ
- `terminalId` กับ `posId` เป็นข้อมูลของ **เครื่องเดียวกัน** → อยู่ในทะเบียนเดียว `PosTerminal`
- เอกสารเก็บ snapshot เครื่องตอนออก (เหมือนชื่อสินค้า / ผู้ซื้อ) → พิมพ์ซ้ำได้ตรงต้นฉบับแม้ทะเบียนเปลี่ยนภายหลัง

## 3. ข้อมูล

```ts
// core/models/pos-terminal.model.ts
interface PosTerminal {
  id: number; // = เลขเครื่อง (terminalId) 1, 2, 3 … ไม่ซ้ำ, แก้ไม่ได้หลังสร้าง
  name: string; // เช่น "แคชเชียร์หน้าร้าน"
  posId: string; // POS ID สรรพากร ('' = ไม่มี; ไม่ซ้ำในร้านเมื่อไม่ว่าง; ≤ 30 ตัว)
  active: boolean;
}

// Sale / CreditNote / Exchange — snapshot ตอนออกเอกสาร (ข้อมูลเก่าไม่มี → ดูขั้นที่ 2)
terminalId?: number | null;
posId?: string; // ที่พิมพ์บนเอกสาร
```

- `posTerminalError()` กติกาเดียว (ฟอร์ม + mock); ร้านจด VAT → เครื่องที่ active ควรมี `posId` (เตือนในหน้าทะเบียน, ไม่บล็อก — T1)
- ลบไม่ได้เมื่อมีกะ / บิลอ้างถึง (ปิดใช้งานแทน); ปิดใช้งานไม่ได้ขณะมีกะเปิด
- `StoreInfo.posId` ถูกย้ายออก (ขั้นที่ 2)

## 4. ข้อตัดสินใจ (ยืนยันครบแล้ว 2026-10-12)

- **T1 ทะเบียนเครื่องอยู่ที่ไหน ใครแก้** — ✅ ยืนยัน 2026-10-12: แท็บใหม่ **"เครื่อง POS"** ในเมนูข้อมูลหลัก `/master-data/terminals`, admin เท่านั้น;
  `GET/POST /pos-terminals`, `PUT/DELETE /pos-terminals/:id`
- **T2 เครื่องรู้ได้อย่างไรว่าตัวเองคือเครื่องไหน** — ✅ ยืนยัน 2026-10-12: admin ตั้งครั้งเดียวที่ **ตั้งค่า → "เครื่องนี้"** เลือกจากทะเบียน, เก็บ
  localStorage `pos.terminal` เหมือนเดิม; `OpenShiftDialog` แสดงเลข + ชื่อเครื่องแบบอ่านอย่างเดียว; เปลี่ยนไม่ได้ขณะเครื่องนี้มีกะเปิด;
  เครื่องที่ยังไม่ตั้ง / ตั้งเป็นเครื่องที่ไม่ active → หน้าขายขึ้น "เครื่องนี้ยังไม่ได้ตั้งเลขเครื่อง กรุณาให้ผู้ดูแลตั้งค่า" และขายไม่ได้
  (server: `X-Terminal-Id` ต้องเป็นเครื่อง active ในทะเบียน มิฉะนั้น `POST /sales` → 400) — บังคับทุกร้าน แม้ปิด `requireShift`
  เพราะใบเสร็จต้องมี POS ID; การผูกเครื่องแบบปลอดภัยจริง (pairing token) ทำตอน SaaS — T5
- **T3 เอกสารพิมพ์ POS ID จากไหน** — ✅ ยืนยัน 2026-10-12: จาก snapshot ในเอกสาร `Sale.posId` / `CreditNote.posId` / `Exchange.posId` ไม่ใช่จาก
  `StoreInfo`; ใบ Z ใช้ทะเบียนเครื่องของกะ (`Shift` เก็บ `posId` snapshot ตอนเปิดกะ); ใบกำกับเต็มรูปที่ออกภายหลังใช้ POS ID ของบิล
- **T4 เลขใบกำกับอย่างย่อรันรวมร้านหรือแยกเครื่อง** — ✅ **ยืนยัน 2026-10-12: (ข) รันเลขต่อเนื่องแยกตามเครื่อง**
  - ใช้กับเลขบิล POS (ใบกำกับอย่างย่อ) เท่านั้น; `INV-` / `CN-` / `EX-` ออกจากเมนูการขายได้ทุกเครื่อง จึงยังรันรวมทั้งร้าน
    (ต่อสาขาตอน SaaS) — แต่ยังเก็บ `terminalId` ตาม T3
  - รันแยกตามเครื่อง + วัน; บิลเก่า `POS-YYYYMMDD-NNNN` คงเลขเดิม (ไม่เปลี่ยนเลขย้อนหลัง) และในรายงานนับเป็นของเครื่อง 1
  - **ทั้งสองแบบรู้ว่าบิลออกจากเครื่องไหน**: T3 เก็บ `terminalId` + `posId` ในเอกสารทุกใบเสมอ (ไม่ขึ้นกับระบบกะ — ตอนนี้รู้ได้แค่ทางอ้อม
    `Sale.shiftId` → `Shift.terminalId` และปิด `requireShift` แล้วไม่รู้เลย) → พิมพ์ POS ID ถูกเครื่อง, กรอง / สรุปยอดต่อเครื่องได้ทั้งคู่
  - T4 จึงเป็นเรื่อง **รูปแบบเลขเอกสารที่สรรพากรต้องการ** เท่านั้น:
  - (ก) รันรวมทั้งร้านเหมือนเดิม `POS-YYYYMMDD-NNNN` — ไม่ต้องแก้เลขบิล / รายงาน; แต่เลขของแต่ละเครื่อง**กระโดด**
    (เครื่อง 1: 0001, 0003, 0007 · เครื่อง 2: 0002, 0004 …) → ถ้าต้องต่อเนื่องต่อเครื่องจะไม่ผ่าน และรายงานภาษีขายเขียน
    "เลขที่ตัวแรก – ตัวสุดท้าย" ต่อเครื่องไม่ได้
  - (ข) แยกต่อเครื่อง `POS<เลขเครื่อง>-YYYYMMDD-NNNN` — เลขต่อเนื่องในแต่ละเครื่อง; รายงานภาษีขายสรุปวันละ 1 บรรทัด **ต่อเครื่อง**
    (`buildSalesTaxReport()` group ตามวัน + `terminalId`), SaaS ขั้นที่ 4 เป็น `POS-<สาขา>-<เครื่อง>-…`
  - คำถามที่ใช้ตัดสิน: "ใบกำกับภาษีอย่างย่อจากเครื่อง POS ต้องรันเลขต่อเนื่องแยกตามเครื่องที่ได้รับอนุมัติหรือไม่" → ต้องรันต่อเนื่อง
  - ขั้นที่ 1–5 ไม่ขึ้นกับข้อนี้; ขั้นที่ 6 ทำแบบ (ข)
- **T5 SaaS** — ✅ ยืนยัน 2026-10-12: ทะเบียนเป็นข้อมูลระดับ **สาขา** (`PosTerminal.branchId`), `BranchInfo` ไม่มี `posId`; server ตรวจว่า
  `X-Terminal-Id` อยู่ในสาขาของ `X-Branch-Id`; ผูกเครื่องด้วย pairing token ที่ server ออกแทนการเลือกเลขเอง
